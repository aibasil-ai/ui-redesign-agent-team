# 安裝指南（UI 重構 Agent 團隊 — 搬移與初始化標準程序）

> **此套件來源**：本套件來自「UI 重構 Agent 團隊」專案（設計書：`2026-11-11-UI重構Agent團隊-設計書.md` v6-final），由 6 個 OpenCode V2 agent＋kit 資料夾構成，設計為可攜套件。**搬家＝複製兩個資料夾＋本指南的必改清單＋填一份 ui-profile**；agent 本體零專案資訊。
>
> **套件組成（一起搬，不可拆）**：
> - `.opencode/agents/ui-redesign/`（6 個 agent：orchestrator、design-analyzer、developer、visual-qa、functional-qa、reviewer）
> - `.opencode/ui-redesign-kit/`（ui-profile.md、ui-profile-範本.md、安裝指南.md、commands/ui-redesign.md、tools/）
>
> **與既有三人組（orchestrator／developer／reviewer）完全獨立並存**：一般功能開發照舊，不動既有檔案。

---

## 安裝必改清單（12 項，逐項執行）

### 1. 複製套件資料夾到新專案

把 `.opencode/agents/ui-redesign/` 與 `.opencode/ui-redesign-kit/` 整個複製到目標專案的 `.opencode/` 下。

**檢核**：

```powershell
Test-Path <新專案>/.opencode/agents/ui-redesign/orchestrator.md          # True
Test-Path <新專案>/.opencode/ui-redesign-kit/ui-profile-範本.md          # True
```

### 2. 填寫 ui-profile.md

複製 `ui-profile-範本.md` 為 `ui-profile.md`（同資料夾），依範本的逐欄說明填寫（專案基本、指令、樣式系統、結構、頁面進入前置、安全不變量、禁改區、設計素材、驗收、產物根目錄、流程程序文件、其他）。**含工具用 Node 絕對路徑**（範本有取得方式的說明）。憑證不得寫進明文；storageState 檔放 gitignored 路徑。

**檢核**：開啟 `ui-profile.md`，確認無 `<待填>` 殘留、指令欄位（test／lint／build／dev server）都是實際可執行的指令。

### 3. `<產物根目錄>` 字串替換（非預設值時必改）

若 ui-profile 的「產物根目錄」**不是**預設 `docs/ui-redesign`：把 **6 個 agent 檔案**權限規則中的 `<產物根目錄>` 字串一併替換成實際目錄（用編輯器全檔搜尋 `<產物根目錄>`）。`run.cmd` 由工具讀 ui-profile 動態解析，**不需替換**。若就用預設值，本項免改。

**檢核**：6 個 agent 檔案內 grep `"<產物根目錄>"` 結果為 0 筆（預設值時 grep `docs/ui-redesign` 應有結果）。

### 4. 測試目錄 ask 路徑（目錄名不同時必改）

若專案測試目錄**不是** `test/`：調整 `.opencode/agents/ui-redesign/functional-qa.md` 權限中的兩條 ask 規則——`test/**` 與 `.worktrees/**/test/**`——**兩條一起改**（雙前綴成對，只改一條會讓 worktree 情境漏防護）。例如測試目錄是 `spec/` 就改成 `spec/**` 與 `.worktrees/**/spec/**`。

**檢核**：`functional-qa.md` 內 grep 舊的 `test/**` 應為 0 筆；兩條 ask 規則存在且前綴對稱。

### 5. 隔離區目錄名（沿用不同名稱時必改）

套件約定隔離區為 `.worktrees/`；若專案沿用不同名稱，**兩處同步**：①各 agent 權限樣式中的 `.worktrees/**`；②工具路徑契約的 `.worktrees` 前綴判定式（tools 內依 §6.2 實作的輸出路徑驗證）。**建議直接沿用 `.worktrees/`，免改。**

**檢核**：6 個 agent 檔案內 grep `.worktrees/**` 與 ui-profile／tools 的約定一致。

### 6. test／lint／build 的 shell allow 字串（非 npm 生態時必改）

權限中的 `npm test*`／`npm run build*`／`npm run lint*`／`npx eslint*` 是 npm 生態預設。非 npm 專案（或指令不同）時，改為 ui-profile 對應指令的字串規則，**涉及三個檔案**：`orchestrator.md`、`functional-qa.md`、`reviewer.md` 的 shell allow 清單。shell 資源是原始指令字串比對，例外規則必須自帶 `*` 萬用字元。

**檢核**：三個檔案中的 allow 字串與 ui-profile「指令」區塊逐字核對（開頭匹配）。

### 7. 工具初始化

執行 `tools/setup.cmd`（初始化包裝：讀 ui-profile 取 Node → **詢問 Chromium 安裝位置** → 產生 `.tool-node.cmd` → `npm install` → `playwright install chromium`）。

**Chromium 安裝位置選項（setup.cmd 步驟 2 會互動詢問）**：

| 選項 | 位置 | 差異 |
|---|---|---|
| 1＝使用者快取共用 | `%LOCALAPPDATA%\ms-playwright`（Playwright 官方預設） | 下載一次約 150MB，本機所有 Playwright 專案共用；瀏覽器二進位在專案目錄之外；移植到新專案不需重新下載 |
| 2＝專案內隔離 | `tools/.browsers/` | 瀏覽器完全放專案內（約 300MB，含完整版＋headless shell＋ffmpeg）；已被 .gitignore 排除；移植到每個前端專案都要重新下載 |

選「2」時 setup.cmd 會把 `PLAYWRIGHT_BROWSERS_PATH` 一併寫進 `.tool-node.cmd`——所有工具執行期自動到該位置找瀏覽器，無需額外參數。**日後想換位置：重跑 setup.cmd 重新選擇即可**（需重新下載瀏覽器到新位置；舊位置檔案可手動刪除）。

或手動（在 tools/ 資料夾內、以**工具用 Node**）：

```powershell
# 以工具用 Node 的 npm 執行（例：C:\nvm\v24.15.0\npm.cmd）
npm install
npx playwright install chromium    # 一次性下載獨立 Chromium，約 150MB
# 專案內隔離時，改為：$env:PLAYWRIGHT_BROWSERS_PATH="<tools>\.browsers"; npx playwright install chromium
# 產生 .tool-node.cmd：一行內容 set "TOOL_NODE=<工具用 Node 絕對路徑>"；選專案內隔離再加一行 set "PLAYWRIGHT_BROWSERS_PATH=<tools>\.browsers"
```

**檢核**：`Test-Path <新專案>/.opencode/ui-redesign-kit/tools/.tool-node.cmd` 為 True，且內容包含正確的 Node 路徑（選專案內隔離時另含 `PLAYWRIGHT_BROWSERS_PATH`）；`node_modules` 內有 playwright、pixelmatch、pngjs。

### 8. `.tool-node.cmd` 加入專案 .gitignore

`.tool-node.cmd` 是機器特定內容（Node 絕對路徑；選專案內隔離時另含瀏覽器位置），**必須 gitignore**。在專案 `.gitignore` 加入：

```
.opencode/ui-redesign-kit/tools/.tool-node.cmd
.opencode/ui-redesign-kit/tools/.browsers/
```

**檢核**：`git check-ignore .opencode/ui-redesign-kit/tools/.tool-node.cmd` 有輸出（被忽略）；選專案內隔離時 `git check-ignore .opencode/ui-redesign-kit/tools/.browsers` 亦有輸出。

### 9. 自我驗證（工具鏈通不通）

跑一次 shot（測試頁截圖）＋一次 diff（兩圖比對）：

```powershell
# 在專案根目錄執行（單獨執行，不串接）
cmd /c .opencode\ui-redesign-kit\tools\shot.cmd --url-file <含 {"url":"…"} 的 JSON 檔> --viewport 1440x900 --out <專案根>\.opencode\ui-redesign-kit\selftest-actual.png
cmd /c .opencode\ui-redesign-kit\tools\diff.cmd --design <任一 PNG> --actual <專案根>\.opencode\ui-redesign-kit\selftest-actual.png --align width --out <專案根>\.opencode\ui-redesign-kit\selftest-diff.png
```

（驗證用的 url-args.json 可先放在 ui-profile 指定的任一 gitignored 路徑；驗證完把 selftest 檔案刪除。）

**檢核**：兩個指令結束碼 0、產出 PNG；shot 能開到目標 URL（或測試頁）。

### 10. 複製命令檔（可選）

把 `commands/ui-redesign.md` 複製到 `.opencode/commands/`（讓使用者直接輸入 `/ui-redesign`，自動以 `ui-redesign/orchestrator` 執行）。不複製也可以手動切換 primary agent 後下達同樣內容。

**檢核**：`Test-Path <新專案>/.opencode/commands/ui-redesign.md` 為 True。

### 11. 產物版控與 .artifacts/ 的 gitignore 行

依專案情況設定（設計書 §9 決策 D1）：

- **產物文字文件要進版控**（是改版的正式文件）：確認「產物根目錄」不在被忽略的目錄下；若專案 .gitignore 忽略整個 `docs/`，可改用精確規則，例如：

  ```
  /docs/*
  !/docs/ui-redesign/
  /docs/ui-redesign/*/.artifacts/
  ```

- **或**把 ui-profile 的「產物根目錄」改指到 repo 內已追蹤位置的新資料夾（例如 `ui-redesign-docs/`），代價是與「文件放 docs」的直覺不一致。
- **`.artifacts/`（截圖 PNG，每輪數 MB）一律 gitignore**，加：

  ```
  <產物根目錄>/*/.artifacts/
  ```

**檢核**：建立一個假產物檔 `git status --short --ignored` 檢查：文字產物被追蹤（可 add）、`.artifacts/` 下的檔案被忽略。

### 12. 開啟 OpenCode 確認 agent 可見

開啟 OpenCode，確認 **6 個 `ui-redesign/` agent**（完整 ID：`ui-redesign/orchestrator`、`ui-redesign/design-analyzer`、`ui-redesign/developer`、`ui-redesign/visual-qa`、`ui-redesign/functional-qa`、`ui-redesign/reviewer`）都出現在 agent 清單，且既有 3 個 agent 未受影響。

**檢核**：agent 切換清單或模型選單能看到上述 6 個 ID。

## worktree 程序引用說明（§8.5 情境一／二）

UI 重構任務可使用 git worktree 隔離。程序有兩個情境，由 **ui-profile 的「流程程序文件」欄位**決定：

- **情境一（有填流程程序文件）**：以該專案程序文件為**主體**執行建立與清除，但一律遵守四條套件插入規則（orchestrator 指令的「worktree 程序」有全文）：
  1. 目錄名固定 `<類型> = ui`（`.worktrees/ui-<slug>`），分支名**刻意不同於目錄**：`ui-redesign/<slug>`。
  2. **建立**時插入 kit junction：

     ```powershell
     New-Item -ItemType Directory -Path .worktrees/ui-<slug>/.opencode -Force
     New-Item -ItemType Junction -Path .worktrees/ui-<slug>/.opencode/ui-redesign-kit -Target <主工作區絕對路徑>\.opencode\ui-redesign-kit
     Test-Path .worktrees/ui-<slug>/.opencode/ui-redesign-kit/ui-profile.md   # 必須為 True
     ```

  3. **清除**時，在 `git worktree remove` **之前**拆除：`cmd /c rmdir .worktrees\ui-<slug>\.opencode\ui-redesign-kit`（與 node_modules 同批，**嚴禁排在後面**）。
  4. 清除閘門：產物已 commit 或經使用者同意丟棄＋kit junction rmdir 成功（失敗即中止），才可 `git worktree remove`。
- **情境二（未填）**：orchestrator 直接使用其指令內建的完整通用程序（建立：worktree add → 依賴 junction 或 npm ci → kit junction → 複製 .env；清除：同意丟棄確認 → 拆 node_modules → 拆 kit junction → worktree remove --force → 確認）。

### ⚠️ kit junction 警告（與 node_modules 同等級）

worktree 內的 `.opencode/ui-redesign-kit` 是**指到主工作區 kit 的 junction**。若在 junction 未拆除時執行 `git worktree remove --force`，Windows 可能**跟隨連結**把主工作區的 `.opencode/ui-redesign-kit`（agent、tools、ui-profile）**整包刪除**——而該目錄多半被 `.gitignore`（`.opencode/`）忽略，**無法從版控還原**。

規則（不可省略、不可後置）：

1. **先** `cmd /c rmdir .worktrees\ui-<slug>\.opencode\ui-redesign-kit`（只拆連結）；
2. **再** `git worktree remove --force .worktrees/ui-<slug>`；
3. rmdir **失敗即中止清除並回報**（判準：路徑本來不存在 → 視為已拆除；存在但 rmdir 失敗 → 中止）。node_modules 的 rmdir 失敗（實體目錄或不存在路徑）可忽略。

安裝後建議向團隊使用者宣導：本專案若同時使用 node_modules junction 與 kit junction，worktree 清除一律由 `ui-redesign/orchestrator` 依上述閘門執行，**不要手動 `git worktree remove --force`**。

## 常見問題

- **`cmd /c .opencode\ui-redesign-kit\tools\xxx.cmd` 執行失敗且訊息指向 Node**：`.tool-node.cmd` 的路徑失效（Node 被移除或升級換路徑）。依第 7 項重新產生（更新 ui-profile 的工具用 Node 路徑→重跑 setup.cmd），**不要**讓 agent 自行改用其他 Node。
- **shot 開不到需登入的頁面**：ui-profile「頁面進入前置」未提供 storageState 或檔案失效。由使用者重新提供 storageState 檔（gitignored 路徑），並更新 url-args.json 的 `storageState` 欄位。
- **`.artifacts/` 的截圖突然不見**：確認不是被 git clean 或 worktree remove --force 清掉（worktree 清除閘門會先確認產物 commit 狀態，但 `.artifacts/` 不進版控、清除即遺失——需要保留的證據先歸檔）。
- **搬家後想升級套件**：對照原設計書（§4 檔案結構、§11 權限模型、§5.3 安裝必改清單）逐檔同步；agent 本體不該出現專案特定資訊，若發現有，那是被安裝時誤改，應還原為零專案資訊版本。
