# 驗測清單（怎麼確認工具運作正確）

> **定位**：本檔提供三層驗測程序——①套件層（可自動、隨時重跑）②OpenCode 層（手動、一次性確認）③端到端試跑（安裝到目標專案後跑一頁）。建議依序執行，全部通過才算「工具運作正確」。

## 第一層：套件層自動驗測（可重複執行）

在套件專案根目錄開啟 PowerShell 執行。**判準：全部 PASS、0 FAIL。**

### 1.1 檔案完整性與 frontmatter

```powershell
$ok=0; $fail=0
function Chk($name,$cond){ if($cond){Write-Output "PASS  $name"; $script:ok++}else{Write-Output "FAIL  $name"; $script:fail++} }

# 6 個 agent
@('orchestrator','design-analyzer','developer','visual-qa','functional-qa','reviewer') |
  ForEach-Object { Chk "agent $_" (Test-Path ".opencode/agents/ui-redesign/$_.md") }

# kit 文件
@('ui-profile-範本.md','安裝指南.md','使用手冊.md','worktree-procedures.md','commands/ui-redesign.md') |
  ForEach-Object { Chk "kit $_" (Test-Path ".opencode/ui-redesign-kit/$_") }

# tools
@('package.json','lib/paths.mjs','shot.mjs','shot.cmd','diff.mjs','diff.cmd','run.mjs','run.cmd','codegen.cmd','setup.cmd') |
  ForEach-Object { Chk "tools $_" (Test-Path ".opencode/ui-redesign-kit/tools/$_") }

# frontmatter 與 subagent deny
# 註：`model:` 欄位由使用者自行決定是否保留（移除後沿用 session 預設模型），因此不列入檢查。
Get-ChildItem .opencode/agents/ui-redesign/*.md | ForEach-Object {
  $t=Get-Content $_.FullName -Raw
  Chk "$($_.BaseName) frontmatter" ($t -match 'description:' -and $t -match 'mode:' -and $t -match 'permissions:')
  Chk "$($_.BaseName) subagent deny *" ($t -match 'action: subagent, resource: "\*", effect: deny')
}

# 功能取捨閘門（F1）：6 個 agent 都必須保留「功能取捨／FQ」規範
$ft = Get-ChildItem .opencode/agents/ui-redesign/*.md |
  Where-Object { (Get-Content $_.FullName -Raw) -match '功能取捨|FQ-' }
Chk "6 agent 功能取捨/FQ 規範" ($ft.Count -eq 6)

# 新增功能閘門（F2）：6 個 agent 都必須保留「NF／新增功能對照」規範
$nf = Get-ChildItem .opencode/agents/ui-redesign/*.md |
  Where-Object { (Get-Content $_.FullName -Raw) -match 'NF-|新增功能' }
Chk "6 agent 新增功能/NF 規範" ($nf.Count -eq 6)

"結果：PASS=$ok FAIL=$fail"
```

### 1.3 端到端工具實測（截圖→比對→腳本→路徑契約）

& $node24 "$env:TEMP\opencode\uirk-probe.mjs" "other/dir/.artifacts/a.png" *> $null; Chk "路徑契約：範圍外拒絕" ($LASTEXITCODE -ne 0)

# 清理：只刪測試 slug；空目錄才逐層移除（不碰 docs/ 其他內容）

foreach ($d in @("docs\ui-redesign","docs")) {

### 3.4 本機 docs 同步與失敗閘門（程序逐項演練）

本套件提供的是 `worktree-procedures.md` 的**人工／Agent 程序，不是自動同步工具**。以下先做唯讀桌面推演、檢查權限與必要資訊，記錄每項「已推演／已實測／未驗證」，不得把文件檢查宣稱為真實合併／同步／移除成功。需實作演練時，另經使用者核准在隔離測試資料中進行，不碰真實分支或既有產物。

| 案例／閘門 | 預期結果 |
|---|---|
| worktree 建立前 | 來源／目的 docs 存在且安全；worktree 外的 ignored 保存根有完整相對路徑、存在／種類、SHA-256 及內容備份；原 docs 複製作起點且校驗一致 |
| 來源新增、目的未新增 | 計畫列新增，Git 成功後只複製核准項目並校驗 |
| 來源單改、目的未改 | 計畫列更新；兩份基準原本不同時列目的原有差異待裁決，不靜默覆蓋 |
| 目的單改（含目的新增／刪除） | 來源未改，不寫入，保留目的 |
| 雙方同改且不同（含目的刪除） | 衝突停下由使用者裁決，不直接覆蓋 |
| 雙方同改且相同 | 已同步，不覆寫，但逐檔校驗 |
| 來源刪除 | 清單逐項請使用者確認；未確認不刪目的，拒刪可記依裁決保留；目的獨有檔不刪 |
| 重新命名／空目錄／檔案目錄互換 | 重新命名按新增＋刪除；空目錄另列；結構衝突停止，不清空目錄 |
| 目的分支不是主工作區分支 | worktree list 找實際 checkout 位置，merge／同步在正確目的；未 checkout／目的不明時詢問，不 git switch |
| 基準缺失／雜湊壞掉／目的 docs 不存在 | 保守停止，不用當前狀態／時間戳猜基準 |
| junction／symlink／斷鏈／硬連結／跳脫／大小寫碰撞 | 複製、刪除前逐層檢查並停止，不跟隨連結或寫到 docs 範圍外 |
| Git 合併失敗／衝突／尚未完成 | 不同步、不拆 junction、不 remove，保留 worktree 與產物 |
| 同步寫入失敗／雜湊不符／來源或目的在核准後變動 | 回報已完成／未解項，保留原內容備份／來源最終快照，不通過清除閘門 |
| 同步成功 | 逐檔核對核准項目的 SHA-256／存在狀態、未核准項未改；回報目的 docs 絕對路徑、清單／未解項、保存根 |
| 保留／直接丟棄 | 保留不強迫合併／同步／清除；丟棄需具體未保留資料與後果明確同意，不把 remove 核准視為丟棄同意 |
| 清除順序與權限 | docs 閘門先通過 → node_modules junction → kit junction → 使用者核准 remove；kit 失敗即中止，node_modules 仍為 junction／類型不明則失敗也中止；保存根不刪、`.opencode/` 不整層回拷 |
| orchestrator 檔案管理權限 | 基準／備份／同步用預設 shell ask，主 session 核准後才執行；edit deny 不變、不碰產品程式碼；拒絕就停止 |
| reviewer 本機證據權限 | `Get-FileHash -Algorithm SHA256 -LiteralPath`、`Get-Item -Force -LiteralPath`、`Get-ChildItem -Force -LiteralPath` 與 `git diff --no-index` 可唯讀比對；串接仍 deny、唯一 edit 仍為自己的報告 |

**證據**：保存每項輸入狀態、計畫分類、所處閘門與預期結果；真實合併／檔案同步只有實際執行後才能標實測通過。不得因 Git status 為空就認定 ignored 產物已安全。

## 常見驗測失敗的排查

| 症狀 | 排查方向 |
|---|---|
| `shot --help` 失敗（結束碼 3） | `.tool-node.cmd` 不存在或 TOOL_NODE 失效 → 重跑 setup.cmd |
| 截圖報「Executable doesn't exist」 | 瀏覽器未安裝或 `PLAYWRIGHT_BROWSERS_PATH` 指向錯誤 → 重跑 setup.cmd 重新選擇位置 |
| agent 沒出現在清單 | 檔案位置錯誤（必須在 `.opencode/agents/ui-redesign/`）或 frontmatter 格式錯誤 |
| `/ui-redesign` 不存在 | 命令檔未複製到 `.opencode/commands/` |
| 權限沒有生效 | 確認 frontmatter 用 `permissions:`（複數、V2 格式），不是 V1 的 `permission:` map |
| edit 落在主工作區而非 worktree | 派工訊息漏了「edit 以 `.worktrees/ui-<slug>/` 開頭」的要求（A1 實測：session 根固定為主工作區） |
| ask 沒跳出來 | child session 的 ask 會自動允許（已實測）；測試檔改由 orchestrator 的 question 流程把關 |
| dev server 突然終止／截圖拍到舊頁或連不上 | 有 agent 自行啟停 dev server（權限層擋不住啟停指令）→ 確認各 subagent 指令含「不得啟停 dev server」；由 orchestrator 重新啟動一次並回報 |
| `shot` 回「--out 輸出路徑不在允許的輸出範圍內」（結束碼 2） | 輸出路徑必須落在 `<產物根目錄>/<slug>/.artifacts/`（worktree 內為 `.worktrees/**/<產物根目錄>/...`）；不要把截圖寫到 `.opencode/`、專案根或 `docs/` 的其他位置 |
