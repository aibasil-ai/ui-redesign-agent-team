# 驗測清單（怎麼確認工具運作正確）

> **定位**：本檔提供三層驗測程序——①套件層（可自動、隨時重跑）②OpenCode 層（手動、一次性確認）③端到端試跑（安裝到目標專案後跑一頁）。建議依序執行，全部通過才算「工具運作正確」。

---

## 第一層：套件層自動驗測（可重複執行）

在套件專案根目錄開啟 PowerShell 執行。**判準：全部 PASS、0 FAIL。**

### 1.1 檔案完整性與 frontmatter

```powershell
$ok=0; $fail=0
function Chk($name,$cond){ if($cond){Write-Output "PASS  $name"; $script:ok++}else{Write-Output "FAIL  $name"; $script:fail++} }

# 6 個 agent
@('orchestrator','design-analyzer','developer','visual-qa','functional-qa','reviewer') |
  ForEach-Object { Chk "agent $_" (Test-Path ".opencode/agents/ui-redesign/$_.md") }

# kit 文件
@('ui-profile-範本.md','安裝指南.md','使用手冊.md','worktree-procedures.md','commands/ui-redesign.md') |
  ForEach-Object { Chk "kit $_" (Test-Path ".opencode/ui-redesign-kit/$_") }

# tools
@('package.json','lib/paths.mjs','shot.mjs','shot.cmd','diff.mjs','diff.cmd','run.mjs','run.cmd','codegen.cmd','setup.cmd') |
  ForEach-Object { Chk "tools $_" (Test-Path ".opencode/ui-redesign-kit/tools/$_") }

# frontmatter 與 subagent deny
Get-ChildItem .opencode/agents/ui-redesign/*.md | ForEach-Object {
  $t=Get-Content $_.FullName -Raw
  Chk "$($_.BaseName) frontmatter" ($t -match 'description:' -and $t -match 'mode:' -and $t -match 'model:' -and $t -match 'permissions:')
  Chk "$($_.BaseName) subagent deny *" ($t -match 'action: subagent, resource: "\*", effect: deny')
}

"結果：PASS=$ok FAIL=$fail"
```

### 1.2 工具鏈環境

```powershell
$ok=0; $fail=0
function Chk($name,$cond){ if($cond){Write-Output "PASS  $name"; $script:ok++}else{Write-Output "FAIL  $name"; $script:fail++} }

$tn = Get-Content .opencode/ui-redesign-kit/tools/.tool-node.cmd -Raw
Chk ".tool-node.cmd TOOL_NODE" ($tn -match 'TOOL_NODE=.*node\.exe')

@('playwright','pixelmatch','pngjs') | ForEach-Object { Chk "node_modules/$_" (Test-Path ".opencode/ui-redesign-kit/tools/node_modules/$_") }

$T=".opencode\ui-redesign-kit\tools"
cmd /c "$T\shot.cmd --help" > $null 2>&1; Chk "shot --help" ($LASTEXITCODE -eq 0)

"結果：PASS=$ok FAIL=$fail"
```

### 1.3 端到端工具實測（截圖→比對→腳本→路徑契約）

> ⚠️ 本段只會建立與刪除 **`docs/ui-redesign/__selftest__/`** 測試產物（slug 用 `__selftest__` 避免與真實頁面混淆）；清理邏輯只刪此目錄，空目錄才逐層移除，**不會碰 `docs/` 下的其他檔案**。

```powershell
$ok=0; $fail=0
function Chk($n,$c){ if($c){Write-Output "PASS  $n"; $script:ok++}else{Write-Output "FAIL  $n"; $script:fail++} }
$T=".opencode\ui-redesign-kit\tools"
$SELFTEST_SLUG = "__selftest__"

# 測試頁與 URL 參數檔（A2 契約）
$html = "<!DOCTYPE html><html><head><meta charset='utf-8'></head><body><h1>Selftest</h1></body></html>"
$html | Set-Content "$env:TEMP\opencode\uirk-selftest.html" -Encoding utf8
New-Item -ItemType Directory -Path "docs\ui-redesign\$SELFTEST_SLUG\.artifacts","docs\ui-redesign\$SELFTEST_SLUG\scripts" -Force | Out-Null
'{"url":"file:///' + ($env:TEMP -replace '\\','/') + '/opencode/uirk-selftest.html"}' |
  Set-Content "docs\ui-redesign\$SELFTEST_SLUG\.artifacts\url-args.json" -Encoding utf8

cmd /c "$T\shot.cmd --url-file docs\ui-redesign\$SELFTEST_SLUG\.artifacts\url-args.json --viewport 1440x900 --out docs\ui-redesign\$SELFTEST_SLUG\.artifacts\r1\actual.png" > $null 2>&1
Chk "shot 截圖輸出 PNG" ($LASTEXITCODE -eq 0 -and (Test-Path "docs\ui-redesign\$SELFTEST_SLUG\.artifacts\r1\actual.png"))

cmd /c "$T\diff.cmd --design docs\ui-redesign\$SELFTEST_SLUG\.artifacts\r1\actual.png --actual docs\ui-redesign\$SELFTEST_SLUG\.artifacts\r1\actual.png --out docs\ui-redesign\$SELFTEST_SLUG\.artifacts\r1\result.json" > $null 2>&1
$pct = (Get-Content "docs\ui-redesign\$SELFTEST_SLUG\.artifacts\r1\result.json" -Raw | ConvertFrom-Json).diffPercent
Chk "diff 同圖 0%" ($pct -eq 0)

'console.log("script ok");' | Set-Content "docs\ui-redesign\$SELFTEST_SLUG\scripts\t.mjs" -Encoding utf8
cmd /c "$T\run.cmd docs\ui-redesign\$SELFTEST_SLUG\scripts\t.mjs" > $null 2>&1; Chk "run 客製腳本" ($LASTEXITCODE -eq 0)

# 路徑契約（合法接受／範圍外、區段邊界、.. 跳脫拒絕）
$node24 = $null
$tnLine = (Get-Content .opencode/ui-redesign-kit/tools/.tool-node.cmd) | Where-Object { $_ -match 'TOOL_NODE=' } | Select-Object -First 1
if ($tnLine -match 'TOOL_NODE=([^"]+)"') { $node24 = $Matches[1] }
$probe = "import { validateOutputPath } from 'file:///" + ($PWD.Path -replace '\\','/') + "/.opencode/ui-redesign-kit/tools/lib/paths.mjs'; validateOutputPath(process.argv[2],'artifacts');"
$probe | Set-Content "$env:TEMP\opencode\uirk-probe.mjs" -Encoding utf8
& $node24 "$env:TEMP\opencode\uirk-probe.mjs" "docs/ui-redesign/x/.artifacts/a.png" *> $null; Chk "路徑契約：合法接受" ($LASTEXITCODE -eq 0)
& $node24 "$env:TEMP\opencode\uirk-probe.mjs" "other/dir/.artifacts/a.png" *> $null; Chk "路徑契約：範圍外拒絕" ($LASTEXITCODE -ne 0)
& $node24 "$env:TEMP\opencode\uirk-probe.mjs" "docs/ui-redesign-something/x/.artifacts/a.png" *> $null; Chk "路徑契約：區段邊界拒絕" ($LASTEXITCODE -ne 0)
& $node24 "$env:TEMP\opencode\uirk-probe.mjs" "docs/ui-redesign/a/../b/.artifacts/a.png" *> $null; Chk "路徑契約：.. 跳脫拒絕" ($LASTEXITCODE -ne 0)

# 清理：只刪測試 slug；空目錄才逐層移除（不碰 docs/ 其他內容）
Remove-Item -Recurse -Force "docs\ui-redesign\$SELFTEST_SLUG" -ErrorAction SilentlyContinue
foreach ($d in @("docs\ui-redesign","docs")) {
  if ((Test-Path $d) -and -not (Get-ChildItem $d -Force -ErrorAction SilentlyContinue)) { Remove-Item $d -Force }
}
Remove-Item "$env:TEMP\opencode\uirk-selftest.html","$env:TEMP\opencode\uirk-probe.mjs" -Force -ErrorAction SilentlyContinue
"結果：PASS=$ok FAIL=$fail"
```

> **判準**：1.1 應 39 項全 PASS；1.2 應 8 項全 PASS（依你的 Chromium 位置選擇，專案內隔離時 PLAYWRIGHT_BROWSERS_PATH 檢查才成立）；1.3 應 7 項全 PASS。任何 FAIL 先排除再往下走。

## 第二層：OpenCode 層手動驗測（一次性）

需在 OpenCode 中操作，確認「設定真的生效」。逐項勾選：

### 2.1 agent 可見性與格式

- [ ] agent 清單出現 **6 個完整 ID**：`ui-redesign/orchestrator`、`ui-redesign/design-analyzer`、`ui-redesign/developer`、`ui-redesign/visual-qa`、`ui-redesign/functional-qa`、`ui-redesign/reviewer`
- [ ] 既有 3 個 agent（orchestrator／developer／reviewer）仍正常、未被新團隊影響
- [ ] `ui-redesign/orchestrator` 的 mode 為 **primary**（可切換為主要 agent）；其餘 5 個為 **subagent**（不出現在 primary 切換清單）
- [ ] 命令檔已裝時，輸入 `/ui-redesign` 會綁定 orchestrator 執行（不需手動切換）

### 2.2 權限實測（分工由權限強制）

依序請各 agent 做「不該做的事」，確認被擋：

- [ ] 請 `ui-redesign/orchestrator` 直接改一個產品檔（如 `README.md` 加一行）→ **edit 應被 deny**
- [ ] 請 `ui-redesign/reviewer` 執行 `git push` → **shell 應被 deny**
- [ ] 請 `ui-redesign/developer` 修改 `.env` → **edit 應被 deny**
- [ ] 請任一 subagent（如 visual-qa）呼叫 `ui-redesign/developer` 派工 → **subagent 應被 deny**（只有 orchestrator 能派工）
- [ ] 請 `ui-redesign/developer` 執行 `npm install` → **shell 應被 deny**
- [ ] 請 `ui-redesign/visual-qa` 執行含 `&&` 的串接指令 → **應被 deny**

### 2.3 ask 行為

- [ ] `functional-qa` 寫入 `test/**`（或你的測試目錄）時**跳出 ask**，且確認框出現在**主 TUI**（不是子 session 內無人回應）
- [ ] 拒絕 ask 後，該項工作停止並回報（改列「建議手動回歸」），不會自行改道
- [ ] orchestrator 的 `git commit`／`git worktree remove` 跳 ask 時，你能正常核准／拒絕

### 2.4 session 工作根（A1 決策）

在目標專案建 worktree 後（或請 orchestrator 執行階段 0）：

- [ ] 派 `developer` 時帶 worktree 絕對路徑為 workdir，其 `edit` **實際落在 worktree 內**（檢查 worktree 內檔案有變、主工作區沒有）
- [ ] worktree 內執行 `cmd /c .opencode\ui-redesign-kit\tools\shot.cmd --help` **可執行**（kit junction 生效）
- [ ] 若 2.4 第一項失敗（edit 落在主工作區）→ 啟動 §7.3 fallback：session 留主工作區、edit 用 `.worktrees/ui-<slug>/` 前綴（權限雙前綴樣式即為此保留）

### 2.5 工具白名單格式

- [ ] 反斜線格式（`cmd /c .opencode\ui-redesign-kit\tools\shot.cmd ...`）可通過
- [ ] 正斜線格式（`cmd /c .opencode/ui-redesign-kit/tools/shot.cmd ...`）可通過
- [ ] 路徑中帶空白的參數（如含空白的 `--out`）不會被權限誤擋

> **判準**：2.1–2.5 全部勾選通過。若有項目不通過，記錄實際行為（哪個 agent、下了什麼指令、被允許還是被擋），回報維護者。

## 第三層：端到端試跑（安裝到目標專案後）

在**目標前端專案**（非套件專案）完整跑一頁，驗證整條流程。

### 3.1 安裝與設定

- [ ] 整層複製 `.opencode/agents/ui-redesign/` 與 `.opencode/ui-redesign-kit/` 到目標專案
- [ ] `ui-profile.md` 已依範本填寫（技術棧、指令、測試慣例、工具用 Node 路徑、產物根目錄）
- [ ] `tools/setup.cmd` 執行成功（Node 確認→Chromium 位置選擇→npm install→瀏覽器下載）
- [ ] 安裝指南第 9 項自我驗證通過（shot 一次＋diff 一次）
- [ ] `.gitignore` 已含 `.tool-node.cmd`（與 `.browsers/` 若選專案內隔離）

### 3.2 單頁試跑（建議挑一個簡單頁）

- [ ] `/ui-redesign` 輸入素材與目標頁，orchestrator 正確讀 ui-profile、詢問 worktree、啟動 dev server
- [ ] 階段 1 產出：`functional-baseline.md`（含測試基準線項數）＋ `design-spec.md`／`design-tokens.json`／`component-mapping.md`／`pending-questions.md`
- [ ] 階段 1.5：決策清單有問你、你的裁決有寫回 pending-questions，規格與 tokens 經你確認凍結
- [ ] 階段 2：developer 有分批實作，且**重用** component-mapping 指出的既有元件（檢查 diff 不是整頁重寫）
- [ ] 階段 3：`.artifacts/r1/` 有 `<viewport>-actual/overlay/diff.png`；visual-report 有 VERDICT＋證據圖路徑
- [ ] 階段 4：`functional-report.md` 的測試項數**不少於** functional-baseline 的基準線、零失敗；`code-review.md` 有需求符合度證據
- [ ] 階段 5：交付彙整四項齊全；commit 訊息**經你審核**；**沒有自動 push**

### 3.3 交付後檢查

- [ ] commit 內含產物文件（`<產物根目錄>/<slug>/` 的 md／json／scripts）
- [ ] worktree 已依程序清除（或你選擇保留並取得路徑）；**主工作區 node_modules 與 kit 完好無損**
- [ ] 既有測試未被刪除或放寬；換行字元未被整檔轉換
- [ ] 建議手動回歸清單已交付（由你人工確認）

> **判準**：3.1–3.3 全部通過＝工具在你的專案上運作正確。

## 常見驗測失敗的排查

| 症狀 | 排查方向 |
|---|---|
| `shot --help` 失敗（結束碼 3） | `.tool-node.cmd` 不存在或 TOOL_NODE 失效 → 重跑 setup.cmd |
| 截圖報「Executable doesn't exist」 | 瀏覽器未安裝或 `PLAYWRIGHT_BROWSERS_PATH` 指向錯誤 → 重跑 setup.cmd 重新選擇位置 |
| agent 沒出現在清單 | 檔案位置錯誤（必須在 `.opencode/agents/ui-redesign/`）或 frontmatter 格式錯誤 |
| `/ui-redesign` 不存在 | 命令檔未複製到 `.opencode/commands/` |
| 權限沒有生效 | 確認 frontmatter 用 `permissions:`（複數、V2 格式），不是 V1 的 `permission:` map |
| edit 落在主工作區而非 worktree | A1 fallback 情境：改用 `.worktrees/ui-<slug>/` 前綴（見使用手冊 §6） |
| ask 沒跳出來 | 檢查是否在子 session 中執行；ask 應回主 TUI |
